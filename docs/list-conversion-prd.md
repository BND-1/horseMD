# 列表类型转换 PRD

## 目标

让用户在富文本编辑时把当前层级的无序列表转换为有序列表、把有序列表转换为无序列表，或一键转为待办清单，而无需删除内容后重新输入列表标记。

这个功能服务于写作中的结构调整：用户通常先快速列点，随后决定改成步骤；或先写步骤，随后发现这些项目不需要顺序。

## 用户入口

- 桌面端富文本模式：在普通有序或无序列表的任一项上右键。
- 悬停右键一级菜单“列表”后，无序列表显示“转换为有序列表”和“转换为待办清单”。
- 悬停“列表”后，有序列表显示“转换为无序列表”和“转换为待办清单”。
- 位于列表中时，菜单不显示“正文”或“标题 1–6”等无法生效的块类型操作。
- 非列表和移动端原生选中文本菜单中不显示该操作。
- 悬停“列表”后，任务列表显示“转换为无序列表”和“转换为有序列表”。

第一版不新增快捷键或命令面板命令。右键入口通过紧凑的“列表”悬停/焦点子菜单提供，避免占用一个默认快捷键，也不改变移动端系统文本选择行为。

## 行为定义

1. 操作对象是光标所在的最近普通列表容器，而不是整篇文档，也不是仅当前一行。
2. 只改变该容器的类型和直接列表项标记。所有嵌套子列表保持原本类型；在子列表操作也不会改动父列表。
3. 转换为有序列表时从 `1.` 开始；转换为无序列表时，原有序号按 Markdown 语义移除。这是目标列表类型的自然语义，不尝试在无序列表中隐藏保存旧序号。
4. 转换为待办清单时，该层直接项目变为未完成的 `- [ ]`；子列表维持原样。
5. 转换作为一笔 ProseMirror 事务，沿用编辑器现有的历史记录机制。
6. 切到源码模式后，只允许当前层级的 marker/checkbox 改变。项目文字、未操作的父子层 marker、原有缩进、紧凑/松散空行和相邻列表必须保留；不能以“合法规范化”为理由重写整棵列表。

## 任务列表转换

任务列表可以显式转换回普通无序或有序列表。转换会移除当前层级的 `- [ ]` / `- [x]` 标记，因此已完成状态不会在普通列表中保留；项目文字和嵌套列表不变。嵌套任务列表不会阻止其普通父层转换，因为父层转换不会触及子层。

## 技术方案

- 新建聚焦模块 `components/editor-list-conversion.js`：
  - 根据 ProseMirror 选择位置找最近列表。
  - 判断当前层级的任务列表边界。
  - 在一笔 transaction 内替换最近列表容器，只同步其直接 `list_item` 的视觉属性与 `bullet_list` / `ordered_list` / task 属性；嵌套列表节点保持不变。
  - 替换前记录选区在列表内的相对位置，替换后显式恢复该选区；不依赖 ProseMirror 在根列表替换时可能映射到末项的默认边界行为。
- `editor-dom-interactions.js` 仅在右键时把当前列表上下文传给菜单状态。
- `Editor.jsx` 只负责渲染菜单动作和调用编辑器内部 API；不引入 App 状态、文件状态或模式切换耦合。转换 transaction 在 dispatch 前提供目标 `doc`，由 `serializerCtx` 建立转换专属 canonical 快照，并以实际右键文字位置映射当前列表层级；不能等待时序不稳定的 `markdownUpdated` 后再猜测。
- `lib/markdown-preservation/lists.js` 对齐转换前后列表行，仅改真正变化的 marker/checkbox 前缀。转换后立即输入时，先提交 marker-only 快照，再把新文字作为普通局部差分应用。完整根因见 [0.12.52 列表转换源码竞态报告](./list-conversion-source-race-regression.md)。
- 明确标记为用户编辑，使现有 `markdownUpdated`、脏状态和保存链路正常工作。

## 非目标

- 不改变 Markdown 源码模式的直接编辑体验。
- 不新增自动检测或自动转换。
- 不自动转换列表、引用列表或表格内的文本结构。
- 不在第一版加入自定义快捷键、命令面板入口或批量跨列表转换。

## 验收标准

1. 在无序或有序列表转换后，只有当前层级的 DOM 与源码类型改变，父列表和嵌套子列表不变。
2. 在任意子列表触发时，只转换该子列表；在父列表触发时，不改变子列表。
3. 普通有序/无序列表可转为待办清单，且仅该层直接项目变为未完成任务。
4. 任务列表可显式转为有序或无序列表，并移除勾选状态；普通段落显示块转换菜单，列表菜单不显示无效的正文/标题项。
5. 现有源码保留、列表排版、移动端构建回归通过。
6. 对同一列表连续执行两次相反转换时，富文本标记和源码列表类型都立即更新，不能只更新源码。
7. 混合“外层松散、内层紧凑”的嵌套列表转换外层后，内层缩进和空行逐字节不变；转换后不等待回调直接逐字输入，切源码、保存、退出并以新进程重开仍保持同一内容和层级。
