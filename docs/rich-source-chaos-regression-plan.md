# 富文本源码保真：混乱编辑回归计划

> 状态：已落地。目的：用接近真实写作的“写—删—回头改—再写—切模式—保存重开”序列，防止只在单向线性输入中通过。

## 执行原则

- 所有自动输入均使用后台 Electron 和 `human-input.mjs` 的逐字符事件；不粘贴、不批量 `insertText`，不获取系统焦点。
- 中文结构测试以稳定的逐字符提交为主；IME 组合输入另由 `test-ime-source-fidelity-ui.mjs` 覆盖，不能混淆两种结论。
- 每个场景都核对四个事实：富文本 DOM 结构、源码 textarea、磁盘文件、全新 profile 重开后的源码。
- 任一阶段失败即输出 fixture、操作阶段与完整源码差异；禁止用“再切一次模式就恢复了”判定通过。

## 场景矩阵

| 场景 | 人类式操作 | 不变量 |
| --- | --- | --- |
| A. 新文档混乱列表 | 标题/正文 → 有序+嵌套 → 退出 → `-` 无序项 → 删空 → 重建 `1.`+嵌套 → 继续 `-` 列表 | 标题、正文、每一层列表都不合并；`-`、`1.` 不变成 `*`、`1)`；无 `<br />` 占位 |
| B. 回头编辑 | 在 A 的前正文、外层项、内层项分别删除一个字符并重新输入 | 后续列表及其他原始块字节不变 |
| C. 继续同一列表 | 对 `-`、`+`、`*` 各 Enter 新增下一项，删除中间项后继续写 | 同一列表 marker 不被 Crepe 默认值覆盖；相邻独立列表不串联 |
| C1. Tab 子列表 | 在 `-`/`+` 父项末尾 Enter 新项后按 Tab，连续写两个子项；其间插入并退出有序列表 | Tab 自动生成的子列表继承父级 bullet marker；不凭空落为 `*`，已存在的显式子级 marker 不被重写 |
| D. 当前层级转换 | 父层/子层分别转有序、无序、待办；紧接着继续输入 | 仅当前层级 marker/checkbox 改变；缩进、空行和未操作子层保留 |
| E. 已有原文 | 加载包含单换行、硬换行、`-`/`+`/`*`/`1)`、紧凑/松散嵌套列表的 fixture 后重复 B–D | 未触及 raw 区域逐字符不变 |
| F. 时序 | 最后输入后立即切源码；富→源→富→源；从富和源两端保存 | 源码、磁盘、重开后三者一致 |

## 节奏

每个关键场景运行三档：连续 35–60ms、常规约 100ms、每个结构操作后停顿约 600ms。连续档专门覆盖 `markdownUpdated` 延迟批处理，常规档覆盖正常用户写作，停顿档避免只修一个竞态窗口。

## 通过标准

1. 所有逐字符输入的可见文本和 ProseMirror 树正确；
2. 源码不新增无授权空行、`<br />`，不替换用户 marker 或有序标点；
3. 保存、全新 profile 重开后完全一致；
4. 对已存在原文，除明确操作的最小 raw 区间外逐字符相同。

## 本轮发现与修复（2026-08-02）

### 复现到的根因

Crepe 会把相邻的 `-`、`+`、`*` 列表序列化为同一类 bullet tree。更关键的是，`markdownUpdated` 不保证每一次 Enter、新增文字、删除操作都单独回调：连续编辑时，它可能把“给 `-` 列表新增一项、给 `+` 列表新增一项、删除 `*` 列表一项”合并成一次 canonical 更新。

旧逻辑假定一次更新只对应一棵列表，使用宽泛 canonical tree 的起点映射回源码。结果是新项被归属到后一个列表，或回退到按行替换；这会把 `+` 改成 `-`/`*`、插入空行和 `<br />`，并在下一次保存后固化为错误原文。

### 修复边界

- `listBlockAt(..., { splitBulletMarkers: true })` 仅供原文修复路径使用，把相邻但 marker 不同的作者列表视为独立块；普通 parser 行为不变。
- 对单次 Enter 新增项，零宽插入若映射到“后一个列表”的开头，会在同层级前一作者列表中落盘；嵌套子项不会误当作前一同层列表。
- 对延迟批量回调，逐个以“首项目文字 + 下一个顶层块文字”为围栏对齐作者列表、旧 canonical 和新 canonical；任一块不能精确对齐时不回写该块，避免整篇 serializer 覆盖。
- 仅在“删除列表项后紧邻列表尾的本次 delta”内忽略 Crepe 的孤立 `<br />` 占位；真实正文/表格中的 `<br>` 不做全文删除。

### 自动化证据

- `scripts/test-rich-source-chaos-fidelity-ui.mjs`：新文档的写、删、重建、回头改、切换、保存、冷重开。
- `scripts/test-rich-source-existing-chaos-ui.mjs`：已有文档混合 `-`/`+`/`*`/`1)`，新增、删除、回头编辑、双向切换、磁盘保存和全新 profile 重开；支持 `CHAOS_BURST=1` 覆盖延迟批量回调。
- `npm run test:rich-source-chaos-ui`：默认的快速、突发和新文档链路组合。
- `scripts/test-markdown-source-preservation.mjs`：加入同一次批量更新跨三个独立列表的纯函数断言。

后续改动列表、源码保真、保存或模式切换时，必须至少运行上述脚本及 `npm run test:markdown-preservation`；不能以富文本视觉正确替代源码、磁盘和冷重开的验证。

### 真实 macOS 前台输入补测（2026-08-02）

CDP 的逐键事件覆盖了渲染器事件链，但它不能替代真实 macOS 前台键盘路径。使用 `CGEvent`、ABC 键盘布局和一个隔离 profile 的已打包应用，实际执行了：`Cmd+N` → 鼠标点入编辑区 → 逐键 `- `、Enter、Tab、继续输入 → `Cmd+/` → `Cmd+A`/`Cmd+C`，再直接读取剪贴板中的源码。

这次补测发现两个 CDP 未暴露的时序/结构边界：

1. 输入规则的临时字面 marker 可能先触发一次 `markdownUpdated`，随后才变为列表；只有确认 serializer 真的改写了对应 marker 后才能消费输入意图，不能在中间回调清掉它。
2. Tab 生成的子列表没有字面 `-`/`+` 输入规则可捕获；在尚无作者子列表行时，应继承紧邻父级的 bullet marker。显式手打的子级 marker 优先级更高。

真实前台回归的最终源码（不使用截图作为断言）为：

```md
intro

- dash-a
- dash-b
1. ordered-a
2. ordered-b
- after-a
- after-b
  - child-a
  - child-b
```

它证明顶层 `-`、有序列表、回到 `-`、以及 Tab 子列表都不会退化为 `*`。实际前台测试会临时接管键鼠；只可在用户明确要求时运行，并始终使用隔离 profile 与独立预览应用。
