# 富文本 → 源码：从特殊规则收敛到通用原则（方案）

> 2026-11-08。用户决定：“不应该有特殊规则，从根上减少并解决这类问题。”
> 依据：三份只读盘点（reprint.js 前后半、编辑器规范化插件 / 序列化器 / 校验器），
> 共约 270 条特殊规则（有少量重叠）。盘点原文在会话 scratchpad，结论汇总于此。

A–D 都不是“Markdown 本身有这么多特殊情况”，而是**同一件事在多处各写一遍、而且是事后预测**。

## 2. 目标：三层，各守一条原则

1. **序列化器只负责“写对”**：对任何可表达的文档，`parse(serialize(doc)) ≡ project(doc)`。所有转义、上下文判断只在这一层，并且在编译阶段（remark handler / `unsafe`）做，不在打印结果上跑正则。
2. **一个投影 `project(doc)`**：文档的 Markdown 含义，由往返定义（`parse(serialize(·))`）加一张在 schema 上声明的“编辑器独有属性”表（标题 id、colwidth、spread、label）。比较、打印、校验全用它。守卫：投影只允许去掉空白 / 空段落 / 边缘换行，**不允许去掉文字**，否则报错（防止序列化器丢内容被“洗白”）。
3. **重打印只负责“少改字节”**：没变的子树原样保留；变了的节点**连同邻居一起**交给序列化器打印、只拼回中间；然后用增量解析**只校验受影响的块**，不过就扩大一级（字符 → 行内段 → 文本块 → 文本块 + 含义变了的邻居 → 父容器 → 整篇）。**不再提前预测哪种情况会错。**

位置映射（C）改为由解析器直接给出（micromark 事件 / mdast position），不再反扫字节。

### P2 设计要点（待 P1 验收后开工）

- `project(doc)` = `parse(serialize(doc))` 后去掉 schema 上声明的编辑器独有属性（标题 id、列表 spread / label / listType、colwidth、`*`/`_` marker、`title: ''` ≡ `null`），再补表格短行（fixTables，V20）。校验改为严格：`parse(候选) ≡ project(编辑器文档)`。
- 往返本身覆盖 V9–V24、V28–V31、V36（换行前空白、空段落、段首段尾换行、相邻列表合并、单元格边缘空白……），这些例外随之删除；V25–V27、V32–V34 随旧 owner 退役；V2（Option A）是用户决定，保留。
- 防“洗白”守卫：除删空白 / 空段落 / 边缘换行 / 编辑器属性外，`project(doc)` 必须和 `doc` 有相同的块结构骨架与相同的非空白文字（含标记）。不同 = 序列化器 bug（如 seed 3908 段落变标题）→ 不保存、记 trace，修序列化器。
- 性能：按顶层块（相邻列表成组）分段计算并缓存，复用 incremental-serialize 的分段。
- 同时处理：列表项 / 引用里排在最前的空段落（P1 撤回的那一步）、空段落不再写 `<br />`。

### P3 第一步：重打印改用投影（2026-11-08，进行中）

- 重打印的“是否相同”（`sameNode` / `sameModuloEditorOnly` 的文本块分支、表格单元格分支）改为 `textblockMeaning`：一个文本块单独投影后的含义，按节点缓存；单元格按真实的单元格类型投影。手写的空白规则（硬换行后行首空白、软换行前后空白）不再参与判断。
- 重打印的校验（`reprintDeps.equivalent`）改为 `areDocumentsEquivalentByProjection`：按顶层块投影（每块缓存，两边相同的块跳过），顶层序列按整篇读回的规则（空段落没了；只隔着空段落的同类列表是一个列表；直接相邻的是两个）。只有 Option A（用户决定）还走旧比较，并且要求去掉粗斜体标记和 `*` `_` 后两边投影完全相同。
- 序列化器统一“写不出”的写法，删掉重打印里的副本（`normalizeForPrint` 的文本块部分）：
  - 文本块首尾只含换行 / 空白的行不写（`trimEdgeLines`，表格单元格除外：边上的 `<br>` 是格子里的空行）；
  - 任何换行前的空白不写（软换行前写出两个空格会变成硬换行——旧序列化器的 bug）；
  - 列表项 / 引用里的空段落不写，被它隔开的同类列表合成一个（和顶层一致）。
- 换行后行首的空白是内容：软换行后写 `&#x20;`（U+200B 哨兵只在文本节点开头才会被读掉，即块首和硬换行后）。
- 相邻同类列表（影子分歧第 1 类）：
  - 编辑器：编辑让两个同类列表**变得**直接相邻时合成一个（`editor-list-join.js`，Typora：Markdown 本来就读成一个；在列表后输入 `1. ` 是续上，不再出现 `1)`）。原本就相邻的（作者用不同符号分开写的）不动；源码模式替换、外部重载、分块加载不触发。
  - 重打印：编辑器里仍然直接相邻的同类列表，换下面那个的符号（`-`↔`*`、`.`↔`)`，有序列表首号写成编辑器的起始号），和序列化器一致（`list-boundaries.js`，不再只限“新相邻的作者有序列表”）。
- 硬换行后行首空格丢失（影子分歧第 2 类）：已修，`a\\\n&#x20; b`，作者的反斜杠换行保留。
- 测试期望按新定义更新 8 处（都是旧例外放过的写法），见 `test-source-reprint-ui` 注释。
- 列表合并按源码判断（`readsAsOneList` → `listsReadAsOne`）：只合并当前源码读成一个列表的那一对（同符号）；作者用 `+` / `-`、`*` 分开写的、在 `*` 列表上面输入 `- ` 的，都保持两个列表（Typora 一样）。
- 结构守卫补充：
  - 只含一张无标记图片的段落 = 图片块（解析器本来就这样读）；
  - 自动链接字面量（`https://…`、`www.…`、邮箱）的链接标记不算变化（输入时是文本，读回是链接）；
  - 文本块中间每个换行记下软 / 硬（表格单元格里都算 `<br>`）：投影把软换行变成硬换行是序列化器的 bug，必须拦下（种子 936 / 236 / 3815）。
- 顶层空段落仍写 `<br />` 占位：写成空行会让增量序列化的分段对不上。
- 单元格：边上或挨着 `<br>` 的纯空白文本不写（`trimCellEdgeBlanks`）。
- U+200B 哨兵只放在可见文字前（只含空白的行写 `&#x20;`，种子 151）；删掉了去掉行尾 `&#x20;` 的正则（它把段落切成两段，种子 34）。
- 旧 owner 的测试改走产品路径（owner 要退役），旧路径的断言只在 `HM_TEST_REPRINT_PRIMARY=0` 时检查。

### P3 第二步：一个定义贯穿到保存检查（2026-11-08 晚）

验收第 4 轮（历史种子 56 个 + 新种子 20 个 + Windows 第 73 批）发现的暂停，根因都是“两个定义”：

- **保存检查也用投影**：重打印引擎用投影验证通过的结果，Coordinator 的完整性检查（`validator.js`）还在用旧比较，两者不一致就暂停。两个方向都出现过：旧比较对（投影守卫漏了换行类型，种子 936），旧比较错（单侧去掉行首空白，Windows 种子 1053）。现在重打印的结果在保存检查里也只问投影（列表结构由投影里的真实解析判断，不再另查列表槽位）；Option A 仍要求 `literalEmphasisOnly`。
- **序列化器**（`remark-text-handler.js` `blankLines`）：换行前的空白逐行处理——同一行前面已有内容（粗体、`&#10;`）时不写；整行只有空白时写一个 `&#x20;`（不写会变成空行把段落切开，原样写会变成硬换行）。
- **重打印不再自己改造节点**：删掉 `normalizeForPrint`（它把换行上的标记全去掉，斜体跨 `<br>` 时空格被挤出斜体，种子 1142 / Windows 5318）。整格打印改为把单元格放进一格的表格里交给序列化器（`printCellFragment`）；只有格内片段补丁仍按换行分段（`printCellSegment`，片段边上的空格在格子里面）。
- **列表边界的遍历 bug**：`list-boundaries.js` 把 ProseMirror `forEach` 的第二个参数（偏移）当成序号，只看得到列表第一项里面，后面各项里相邻的嵌套列表既不分开也不合并（种子 5210：编辑器两个列表，旧写入器写成一个，没有报警）。

剩下的风险（P4 处理）：旧比较把**直接相邻**的同类列表也当成一个列表，旧写入器的结果因此可能把编辑器里两个列表写成一个而不报警；现在编辑产生的相邻已在编辑器里合并，作者原本分开写的两个列表仍依赖重打印先处理。

### P2 收尾：所有写入方都用投影判断（2026-11-09）

- `validateTransactionMarkdown`（Editor）和 Coordinator 的完整性检查（`validator.js`）对**所有**候选都用投影判断“含义相同”（没有注册投影器时才用旧比较）。旧写入方仍要过列表槽位检查（作者的编号写法）。影子数据：新种子里两者不一致的 337 次，记录到的全部是“旧比较说不同、投影说相同”（换行前空白、空段落、单元格边缘），没有一次反过来——旧比较只会多暂停，唯一更宽的是“直接相邻的同类列表算一个”，这条风险随之消失。
- 列表合并只针对“输入 / 删除带来的相邻”：**改了类型**的列表（有序 → 无序、任务 → 普通）保持它自己，写出时和邻居分开（`editor-list-join.js` `converted`）。之前转换后的列表会并进上面的任务列表，再转换一次连它一起变成任务（`test:list-conversion-ui`，这个测试不在回归清单里，P3 期间一直失败没被发现）。
- 验收补齐：
  - `test-projection-audit-ui` 增加“打开不改，字节不变”：271 个仓库文件 + 规范例子全部原样；
  - `test:mark-combinations-ui` FULL=1：765 592 例通过；
  - 性能对 P0（main 254511d）：打字中位数相同，改标题快约 30%，其余在误差内，增量序列化 0 次不一致；
  - 回归清单外的 UI 测试全扫一遍（`sweep-unlisted-ui.mjs`），失败的逐个和 P0 对比。
- 全量扫描结果（2026-11-09，196 个清单外 UI 测试）：150 过，46 失败；和 P0 对比，23 个 P0 也失败（早已存在），23 个是这次新增。新增的处理：
