## 原结论（2026-08-06）

当时**未能精确复现**「保存后重开发生结构变化」。以下记录保留为历史证据；其中“斜杠菜单路径正常”已被 2026-08-11 的连续跨块编辑复现推翻，不能继续作为当前结论。

## 已确认的解析机制

Markdown 里如果代码块的**结束围栏后同一行直接跟正文**（` ```尾部正文`），remark 解析时该行不是合法围栏行，会继续向后寻找围栏直到文档结束——**后面所有内容（含正文）被并入代码块**。这正是用户描述「最后一个代码块把后面的正文包含进去」的渲染机制。

但是：正常的保存路径（斜杠菜单、粘贴、输入规则、编辑代码内容）产出的源码**结束围栏后都有换行**，不会触发该机制。因此「重开吞正文」的根源一定是**保存到磁盘的源码本身围栏结构损坏**（围栏缺失或围栏后换行丢失）。

## 用户现场文件（`置身钉内/测试文件/`）

- `代码测试.md`：**两段代码完全无围栏**，第一段结尾 `register()` 与第二段开头 `import bpy` **粘连在同一行**（`register()/import bpy`）。怀疑是「粘贴第二段代码时未在上一行末尾换行」或「插入代码块失败退化为普通文本」产生的损坏态。
- `代码测试1.md`：两个完整围栏代码块（约 130 行/块），是手动修复后的版本。打开 → 编辑 → 保存 → 重开均正常。

## 已排查且正常的路径

以下场景均用真实 Electron（CDP 逐键/真粘贴）+ 保存 + 完整重开验证，源码与磁盘逐字符对比、围栏数量与空行分隔均正确：

- 斜杠菜单插入 `/js`、`/code`（当时只测插入→保存→重开，**没有覆盖创建后连续编辑其他块，因此覆盖不足；RS-40 已补齐**）
- 手打 ``` 输入规则（单独场景有输入规则转义问题，见下）
- 真粘贴含两个代码块的 Markdown（`editor-md-paste` 路径）
- 代码块内容相同 / 不同、多行（130 行）代码块
- 空代码块、代码内容含三反引号（remark 自动加长围栏为 ````）
- Mermaid 预览块、文档末尾插入、文档中间插入、已有文件内插入
- 编辑第一个/第二个代码块内容后保存
- 纯函数层 `preserveRichMarkdownSource` 单行/多行代码块内容编辑

## 相关但必须分开的反引号同步问题

- **HorseMD 0.13.26 已修复**：逐字输入一个/三个反引号后做部分删除、全部删除、继续输入、立即切源码或立即保存，不再造成双快照分叉、保存暂停和源码按钮锁死。专项见 `backtick-source-sync-lock-regression.md`。
- **本报告仍在跟踪**：真正把三个反引号转换成 fenced code block 的输入规则，以及已经损坏的结束围栏为何会吞并后文。不能因为“反引号删除同步已修”就宣称围栏创建/吞正文也已解决。
- 粘贴**无围栏纯文本**代码的行首缩进语义属于另一条路径，也不能和 fenced code block 围栏损坏混在一起处理。
