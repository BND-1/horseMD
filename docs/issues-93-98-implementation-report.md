# Issues #93, #96, #97, #98 实施与验证报告

## 范围

本轮逐条处理四个独立问题，保持 Crepe 生命周期、Markdown 原文保真、源码/富文本切换、PDF 文档构建和移动端平台契约不变。

## #93 行内代码

旧版已能阻止多个反引号被输入规则吞掉，但输入插件只识别“先输入两个反引号，再输入正文”的特殊路径。用户按标准 Markdown 顺序逐字手打 `` `awdawdwa` `` 时，首尾反引号和中间正文都会留在普通文本节点中，实际没有创建 `inlineCode` mark。此前 UI 自动化也错误地多输入了一个左反引号，并一次性注入正文，没有覆盖真实键盘路径。

修复把输入状态拆为“等待首个正文字符”和“正在编辑行内代码”：第一个左反引号先原样保留，紧接着逐字输入正文时再转换为标准 `inlineCode` mark，右反引号明确退出。仅在编辑态且光标位于该 mark 内时绘制两个 ProseMirror widget；widget 不进入文档、复制结果、Markdown serializer 或 source offset 映射。光标移动、编辑器失焦或输入闭合反引号后自动清除等待/编辑状态，连续普通反引号仍按字面保留。

补充真实“闭合后继续输入”时发现，ProseMirror 已经退出 `inlineCode`，但原文保真映射在行末只能锚定最后一个可见字符，会把新增正文插到闭合反引号之前，源码因而变成未闭合代码。现在行末零宽插入会依据整篇可见字符映射跨过反引号、强调、删除线、链接和关闭 HTML 等不可见闭合语法，同时停在尾随硬换行空格之前。该规则同时覆盖代码、强调和链接，不依赖关键词或局部语法猜测。

后续补齐与 Typora/常见成对符号编辑一致的方向键边界：光标位于行内代码尾部时按 `→`，或位于首部时按 `←`，会在同一个 ProseMirror 文档位置清除 `inlineCode` stored mark 并退出编辑态。这样不会为了表示视觉左右侧而插入隐藏字符，也不会跳过相邻正文；代码内部方向键和带修饰键的导航仍交给 ProseMirror 原生处理。

组合回归随后发现，若在文档末尾按 Enter 后直接以行内代码起笔，左反引号会先序列化为独立的 `\`` 临时段落，首个正文字符再把它转成真正的 `` `f` ``。旧保真映射仍按可见字符定位，但临时反引号段落没有稳定可见锚点，可能把新段落写到上一段行尾。全文逐字相同时可确定性采用下一 canonical 结果；全文因紧凑单换行或额外空行而不同时，只要最后一个独立单行块与 canonical 局部逐字相同，就直接替换该行，不触碰前文。专项测试使用带非 canonical 前缀的真实段落链，要求 ``上一段\n\n`feaef`212afea``、保存重开及 rich→source→rich→source 的末尾 raw offset 连续 10 次保持不变。

## #96 标题间距

此前标题使用固定 `margin-top: 1.75em` 和 `margin-bottom: 0.55em`，段落间距设置无法控制它。新增独立 `headingSpacing` 偏好、范围校验、预设、CSS 变量和实时应用函数。默认值取与旧样式视觉等价且可由 0.1 步进精确表达的 `1.8em`，避免升级后明显改变既有排版；标题后的较小间距按同一变量派生。

设置同时出现在编辑器排版页和状态栏排版面板，设置页真实预览与正文读取同一 CSS 变量。

## #97 PDF

资源状态过去只暴露一个 timeout 布尔值和 failedImages 数量，UI 将两者合成“X 张图片失败”，会把仍在加载写成失败，甚至出现“0 张失败”。现在主进程分别返回总数、仍在加载数和失败数；UI 分别提示，零图片不显示警告。

PDF 预览继续采用每个 renderer 最新请求胜出。被后续设置替代的请求返回 `stale`，renderer 将其视为正常取消，不进入错误状态。真实 UI 测试在首个预览尚未完成、导出按钮禁用时连续切换页眉和页脚，最终只接受最新 PDF。

## #98 复制、撤销与会话恢复

Crepe 代码块按钮原先直接调用浏览器 Clipboard API，HorseMD 的监听器无论实际写入结果如何都会显示“已复制”。现在捕获按钮点击，从对应 ProseMirror `code_block` 读取完整文本，并通过 preload 的原生剪贴板 IPC 写入；成功后才显示反馈。

后续长代码回归发现，旧节点查找只检查 `nodeAt/nodeAfter/nodeBefore`，没有检查 `ResolvedPos` 所在的父节点。短代码恰好能命中，超过约 50 行的 CodeMirror 开始虚拟化后，定位失败会回退读取当前 DOM 中约 30–65 个 `.cm-line`，于是 100 行以上的 `settings.json` 被静默截断。修复后先从当前位置逐层向上查找 `code_block`，再按 DOM 与 ProseMirror 中代码块的文档顺序兜底；虚拟 DOM 文本回退已经移除。真实 UI 回归使用 120 行 JSON，并明确断言 DOM 行数小于源码行数时，系统剪贴板仍逐字等于完整 122 行代码。代码块内部的 `Cmd+A/Cmd+C` 与从首行真实 Shift 选择 65 行也分别校验系统剪贴板；两者由 CodeMirror 文档状态处理，原本即可跨越虚拟 DOM，不应为修复按钮而接管或改写其原生选区复制。完整事故、停止条件和测试基础设施注意事项见 [长代码块复制截断事故复盘](./long-code-copy-virtualization-regression.md)。

富文本 copy 的 HTML 通道保留内联样式。0.12.46 曾把 Milkdown serializer 的结果直接写入 `text/plain`，试图保留粗体、行内代码等 Markdown 标记；但 serializer 输出的是块级 Markdown，不是选区纯文本，因此段落会带额外换行，有序列表会带自动生成的 `1. `。0.12.47 改为三通道契约：`text/plain` 使用浏览器选区的可见文字，`text/html` 保留富文本样式，`text/markdown` 单独保存结构化 Markdown，HorseMD 内部粘贴优先读取该通道。完整事故记录见 [0.12.46 剪贴板 MIME 回归报告](./clipboard-mime-regression-0.12.46.md)。

Crepe 当前构建已经加载官方 history 插件，Electron 菜单也保留原生 undo/redo role。真实键盘测试证明普通富文本输入可由 `Cmd+Z` 撤销，因此未重复安装历史插件或新增第二套撤销栈。

新增默认开启的 `restoreSession` 偏好。关闭后，`useAppLifecycle` 跳过历史路径和未保存草稿的恢复；打开路径监听仍在 `appReady` 前注册，因此 Finder、资源管理器、文件关联和命令行显式打开不受影响。

## 0.12.34 追加根因修复

上一轮自动化在切换后统一等待约 700ms 再输入，错误地避开了真实用户会遇到的时间窗口。源码切回富文本后，光标恢复任务会在 `requestAnimationFrame` 以及 90、220、450、700ms 重试；用户若已开始输入，后续重试仍会覆盖新光标，表现为字符乱序、段落合并或光标相差一行。现在首次恢复在 layout effect 中同步完成；检测到键盘、输入法或指针交互后，所有剩余重试立即失效，不能再覆盖用户选择。

复杂原文中的另一个合并问题与竞态无关。旧保真逻辑要求整篇文档的可见行全部一致，表格对齐空格、紧凑列表与宽松列表等无关序列化差异会让局部“插入新段落”降级为字符拼接。代码围栏又属于不可见语法边界，进一步造成新段落被接到围栏前的上一段末尾。现在中间块插入只验证相邻可见块，并识别原有代码围栏间隙；不会因文档其他位置的格式差异而改写局部结构。

光标偏移还来自位置模型：硬换行和行内图片在 ProseMirror 中占一个位置，但不出现在 `textContent` 中。旧映射按文本长度计算，经过这些节点后必然偏移。当前映射改为逐字符、逐行内原子节点的单元序列，源码 raw offset 与 ProseMirror position 都通过同一序列换算。

追加验证覆盖：

- 源码切回富文本后零等待输入 Enter 和 `X`，并分别跨过 90ms、220ms 重试窗口继续输入 `Y`、`Z`。
- 包含非规范表格对齐、紧凑列表、硬换行和后继代码围栏的原文，在中间插入段落后其余源码逐字不变。
- 硬换行前后、行内图片后方的双向 raw offset 映射。
- 上述零等待场景使用 10 个独立 Electron 进程重复验证，避免共享状态掩盖问题。
